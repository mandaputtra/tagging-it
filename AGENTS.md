# AGENTS.md — Tagging It

Freemium QR/barcode generator: create codes one-by-one or in bulk, each with a user-customizable text label, print via the browser print dialog to a laptop-connected printer. Free tier is 100% client-side (browser storage, no server sync); premium adds server sync.

## Workflow directives (user standing preferences)

- **TDD first**: write failing unit tests before implementation. Follow Phoenix testing best practices: https://phoenix.hexdocs.ph/testing.html
- **Call-graph before every plan**: read `.agents/skills/call-graph/SKILL.md` and draw the data-flow graph (A → E → R) before designing or building any non-trivial flow. Output format: plain `ts` block, indented `→` arrows, Production + Tests sections. Code must match the graph.
- **Wayfinder**: this project is charted on GitHub issues. The map is issue #1 (`wayfinder:map` label); tickets are its sub-issues (`wayfinder:research|grilling|prototype|task` labels). Work one ticket per session; claim (assign to yourself) before starting. See the wayfinder skill.
- **Ponytail (always on)**: before writing any code, stop at the first rung that holds: (1) does this need to exist at all? (2) already in codebase? reuse it. (3) stdlib? use it. (4) native platform feature? use it. (5) already-installed dep? use it. (6) one line? one line. (7) only then: minimum that works. No unrequested abstractions, no boilerplate. Deletion over addition. See `.agents/skills/ponytail/SKILL.md` for full rules.

## Stack

- **Phoenix 1.7** (Elixir 1.20, OTP 29), Bandit, LiveView. `mix phx.server` to run (port 4000).
- **No Ecto / no asset build pipeline** (scaffolded with `--no-ecto --no-assets`). Do not add Ecto unless a ticket explicitly requires DB work — free tier is browser-only.
- **bwip-js** (client-side, MIT) — the only lib covering the v1 set: QR, Code 128, Code 39, EAN-13, EAN-8, UPC-A, PDF417, DataMatrix, Aztec. Use `bwipjs.toSVG()` for vector output (crisp at print DPI). Load from CDN in the prototype; bundle properly when the real app needs it.
- **IndexedDB** via the `idb` wrapper — free-tier storage. Stores: `batches`, `codes`, `meta`; client UUID primary keys; `updatedAt` + dirty flag for future delta sync.
- **Print**: HTML + print CSS through the browser dialog. No PDF library. Inches are exact in `@page`; mm quantizes ~+0.24%. Safari < 18.2 ignores `@page`; avoid `landscape`/`portrait` keywords. See `docs/research/print-layout.md`.

## Domain language

Defined in `CONTEXT.md`. Key terms: **Code** (a generated barcode + its fields), **Batch** (group created from one **Batch template**), **Field** (`{field_name, value}` pair), **Field map** (resolved ordered field list stored per code), **Label** (printable barcode + fields at a **Label size**), **Code data** (the encoded value, generated by strategy: custom pattern or ULID), **Sync** (premium server replication). Use these terms exactly; update CONTEXT.md when new terms crystallize.

## Architecture decisions (from research, `docs/research/`)

| Decision | Choice |
|---|---|
| Client barcode lib | bwip-js (9/9 formats, SVG/canvas/PNG) |
| Sync payload | Structured data (symbology + text + options), NOT image bytes; no server-side generation in v1 |
| Free-tier storage | IndexedDB via idb; codes/batches/meta, client UUIDs, `updatedAt`+dirty |
| Print | HTML + print CSS; full-sheet stock (Letter/A4) default; custom sizes best-effort + calibration |
| Premium | `phx.gen.auth` + Stripe Billing (stripity_stripe); single `POST /api/sync`; per-record last-write-wins; `require_premium_user` plug |
| Label fields | Free-form `{field_name, value}`; per-batch template pre-fills; resolved map per code; fixed zones + order-only layout |
| Label sizes | Preset catalog + custom W×H fallback (single-label-per-page for custom) |
| Bulk input | Sequence-generation form (first-class) + paste-list; CSV import deferred |
| Batch lifecycle | Batch object + code rows, `batchId` index |
| Print selection | Batch-level print all + subset via checkboxes |
| Prototype verdict | Mix of variant B (sheet grid) + C (live field editing) — the print flow should show a full sheet with live-editable label fields |

## Design system

Copy of Notion's design analysis at `docs/notion-DESIGN.md` (not a literal Notion-brand directive — it's the taste reference the user chose). Key takeaways for this app:

- **Colors**: signature purple `#5645d4` reserved for the primary CTA only; deep navy `#0a1530` for hero bands; pastel card tints (peach, rose, mint, lavender, sky, yellow) for feature cards; neutral ink/charcoal/slate/steel text ramp; hairline borders `#e5e3df`.
- **Typography**: Notion Sans / Inter fallback; 600-weight headlines, 500 buttons, 400 body; tight leading (1.05) + negative letter-spacing on display sizes; generous body leading (1.55).
- **Geometry**: buttons are 8px-rounded rectangles (NOT pills); cards 12px; pill radius only for tabs/badges.
- **Elevation**: flat default (hairline border), subtle hover, deeper shadows only for hero mockups/modals.
- **Spacing**: 4px base unit, 8px increments; section rhythm 64–96px.
